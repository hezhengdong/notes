    如何写好技术文章

    不知道，自己也一直在探索。

    首先，格式要正确。

    • 中文技术文档的写作规范

    对于内容

    图片 > 文字、代码

    图片是最直观的。同样的内容，一张清晰直观的图片要比大段文字效果好很多。

    如流程图、类图、时序图等。

    mermaid 文生图工具

    当然，自己先看懂自己写的文章。

    笑话：不加注释的代码，第一天只有自己与上帝能够看懂，一段时间后，只有上帝能看懂这段代码。

    自己之前也遇到了这样的问题，大段文字，大段带详细注释的代码，现在一眼也不想看，自己也正在改进这个毛病。

    并不是篇幅越长越好，除非你要写本类似字典作用的工具文章。

    如果感觉词不达意，可以让 AI 帮忙表达。

    当然，主要内容还是自己生成的，个人认为 AI 在写作中的作用，仅仅是词不达意时，帮助将“心领神会”但是写不成通顺清晰条理文字的内容表达出来，并不能代替作者生成内容。

    什么样的笔记值得做？

    不值得做的

    • 类似 Java 反射 API 如何使用，这种玩意要用网上查就行，写笔记里完全是浪费生命（浪费时间）浪费公共资源（浪费磁盘浪费带宽）

    为什么不直接用别人的笔记？

    如果别人的笔记完美契合自己所需，当然可以把别人的笔记保存下来，自己也省事了。

    但是！这种情况几乎不可能！关于每块知识点，每个人都有自己认为的重点，重点指的是“点开任督二脉，理解一个知识点在逻辑上的重要思考点”。

    哪些部分是“任督二脉”每个人都不一样，只有自己才能知道

    • 举个“任督二脉”的理解。
      • 例如锁相关知识的任督二脉。锁无非就是加锁方法与解锁方法，加锁时检查锁是否被占用、解锁是修改“锁是否被占用”的表示。任何锁相关知识都离不开“加锁”“解锁”“锁标识”。意识到这一点，那么 JUC、Redisson、MySQL 等方面都有了切入点！

    之前用黑马讲义踩的坑。

    黑马讲义几万字，怎么可能记得住，很多很多都是完全没用的，大而全的笔记最终为难的是自己。

    自己要提取出重点记下来，方便复习。

    为什么要做笔记？

    “输出才能让自己的知识学习有导向，有清晰的结构和框架。”
